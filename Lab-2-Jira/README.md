## 1. Project Overview

The Local Sports Tournament & Bracket Manager is designed to provide a structured platform for managing local sports tournaments, from bracket creation to match completion.

The system allows Tournament Directors to generate seeded single-elimination or double-elimination brackets based on team rankings. Match Officials can record live and final match scores, while league standings and tiebreaker rankings update automatically after each result. Team Captains can view the current brackets and standings to track their team's progress.

## 2. Objectives

- Organize tournament activities using an Agile workflow.
- Create and prioritize a product backlog using epics and user stories.
- Estimate task complexity using story points.
- Divide the backlog into planned sprints.
- Track progress using Jira boards and burndown charts.
- Review sprint outcomes and reflect on the team's simulated performance.

## 3. Tools Used

- **Jira:** Backlog management, sprint planning, task tracking, reports, and burndown charts.
- **Agile methodology:** User stories, story-point estimation, prioritization, and sprint execution.

## 6. Results and Observations

### Effort Estimation

The estimates reflected the relative complexity of the backlog items. Bracket Generation and Calculate Tiebreakers required more complex logic and uncertainty, so they were assigned 8 points. Record Match Score and Update League Standings received 5 points each, while Bracket Validation and View Bracket & Standings received 3 points each.

Since the exercise was simulated, the estimates could not be compared with actual development hours.

### Backlog Prioritization

High priority was assigned to the five stories supporting the core tournament workflow. Viewing brackets and standings was assigned medium priority because it improves visibility for Team Captains but is not part of the core score-processing logic.

### Sprint Execution

Sprint 1 focused on generating brackets and processing match results. Sprint 2 focused on validation, tiebreaker calculations, and displaying tournament information. All six stories were progressed through the planned workflow.

### Burndown Chart Analysis

The burndown charts showed the remaining story points reaching zero rapidly in both sprints, ahead of the ideal guideline. Because the sprints were simulated and the tasks were moved through the workflow quickly, these charts should not be interpreted as accurate measurements of real development capacity.

They demonstrate how burndown charts can be used to visualize remaining work and compare progress against a planned trajectory.

## 7. Conclusion

This exercise demonstrated how Jira can be used to manage the development process for a Local Sports Tournament & Bracket Manager. The requirements were organized into epics and user stories, prioritized, estimated using story points, and divided into two simulated sprints.

Jira boards and reports were used to track task progress and visualize sprint performance. Overall, the exercise provided practical experience with Agile backlog management, sprint planning, estimation, progress tracking, and retrospective analysis.
